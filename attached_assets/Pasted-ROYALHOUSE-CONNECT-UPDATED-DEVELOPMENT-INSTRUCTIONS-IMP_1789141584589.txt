ROYALHOUSE CONNECT — UPDATED DEVELOPMENT INSTRUCTIONS

IMPORTANT

Do not rebuild the project from scratch.

Continue from the existing Royalhouse Connect application and upgrade/refine the current system based specifically on the requirements, problems, ideas, and workflow discussed in the Connect Team meeting with Rev.

The goal is to move from the current prototype toward a real, scalable church management platform that can eventually be used across Royalhouse Chapel branches worldwide.

The system must be designed around the actual church workflow rather than simply adding random features.

5. AUTOMATIC CONNECT TEAM INPUT

The Connect Team must be able to automatically input information into the system without having to repeatedly type the same information manually.

The interface should use structured forms, dropdowns, checkboxes, selections, and automated fields wherever appropriate.

For example:

Instead of requiring a Connect Team member to type:

“I called Brother John and he told me he was sick and would like someone to visit him.”

The system should allow:

Person:
Brother John

Call outcome:
Spoke with visitor/member

Situation:
Sick

Additional need:
Visitation requested

Prayer needed:
Yes

Pastoral attention:
Yes

Next follow-up:
[Date]

Notes:
[Optional free-text field]

Then the system automatically records the interaction.

The system should also trigger the appropriate next action based on the selected information.

7. AUTOMATIC TRIGGERS

The system must support workflow triggers.

Example:

IF:

Connect Team member selects “Sick”

THEN:

* Record the interaction
* Flag the person's profile
* Create appropriate follow-up
* Notify the appropriate person/team if configured

Another example:

IF:

Connect Team member selects “Needs Pastoral Follow-up”

THEN:

* Create pastoral task
* Notify authorized pastoral/admin users
* Display the task on the relevant dashboard

Another:

IF:

Connect Team member selects “Interested in Foundation School”

THEN:

* Update Foundation School interest status
* Create follow-up
* Notify the appropriate coordinator if configured

Another:

IF:

Follow-up becomes overdue

THEN:

* Notify Connect Team member
* Notify Connect Team leader where configured
* Display overdue status on dashboard

Build this as a flexible workflow engine rather than creating separate hard-coded logic for every situation.
